# ExpertOS moonshot roadmap

Milestones are **ideas for investigation**, not promises or completed features.

| Phase | Goal | Test to prove it works |
|---|---|---|
| 0 (implemented) | Transparent scoring prototype | Unit tests pass; unverified ideas are not ranked as proven |
| 1 | Local-first workspace and evidence import | Creators can remove data and trace every problem statement to its source |
| 2 | Interview-to-demand graph | Domain experts agree with extracted pains and can correct mistakes |
| 3 | Expert-guided product studio | Independent reviewers judge output useful and accurate, not generic |
| 4 | Open offer-validation toolkit | First-time creators can run ethical real-world price tests |
| 5 | Portable storefront and content pipelines | Products can move between hosts without vendor lock-in |
| 6 | Learning and quality evaluation loop | Improvements in customer outcomes can be measured without exposing PII |
| 7 (moonshot) | Open creator business protocol | Multiple independent tools interoperate through shared open standards |

## Open research questions

1. How do we tell *reported enthusiasm* from *real payment intent*?
2. How do we protect domain experts from hallucinated professional advice?
3. Can a local-first approach keep a useful evidence graph without leaking identities?
4. How can creators own their product and customer relationship without getting trapped by checkout providers?
5. When should the system say **do not launch this idea**?

## First three useful community issues

- Design a `SourceEvidence` JSON Schema with consent and deletion metadata.
- Prototype a side-by-side evidence viewer for two product concepts.
- Implement repeatable, anonymous interview-to-problem extraction evaluations using synthetic fixtures.
